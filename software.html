Firmware Architecture

The portfolio firmware is organized into small modules. The top-level application is intentionally implemented as a finite state machine (FSM) rather than scattered button logic. Low-level modules hide motor PWM, actuator GPIO, button debounce, encoder RPM calculation, and UI update behavior.

ModuleResponsibility
app.c / app.hApplication state machine, safety interlocks, speed selection, and closed-loop PI speed control.
motor.c / motor.hStarts TIM1 PWM, sets duty cycle, sets forward direction, and stops the motor.
actuator.c / actuator.hWakes actuator driver, commands lock/unlock, disables actuator output, and reports fault input.
buttons.c / buttons.hDebounces three active-low user buttons and reports one-shot press events.
encoders.c / encoders.hStarts TIM3/TIM4 encoder mode and converts count deltas into RPM values.
ui.c / ui.hInitializes display GPIO/backlight and provides a single status update interface for the TFT layer.

Main Loop

The main loop follows a simple cooperative scheduling style. CubeMX initializes clocks and peripherals, then calls APP_Init(). The infinite loop repeatedly calls APP_Update() with a small delay. Inside APP_Update(), the firmware updates buttons, samples encoders, checks fault and door conditions, handles button events, runs the PI controller if the system is running, and updates the UI.

int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_ADC1_Init();
    MX_SPI1_Init();
    MX_TIM1_Init();
    MX_TIM3_Init();
    MX_TIM4_Init();
    MX_USB_DEVICE_Init();

    APP_Init();

    while (1)
    {
        APP_Update();
        HAL_Delay(5);
    }
}

StateMeaningAllowed Actions
STOPPED_LOCKEDMotor off; system records lock state as locked.Start if door closed, unlock actuator, cycle speed presets.
STOPPED_UNLOCKEDMotor off; system records lock state as unlocked.Start if door closed, lock actuator, cycle speed presets.
RUNNINGMotor on; PI controller regulating output shaft speed.Stop motor. Lock/unlock blocked. Door opening causes immediate stop.
FAULTFault detected from actuator driver or safety logic.Motor and actuator disabled until fault clears.

Coding Style

The firmware uses C with a modular driver-like structure. Each module exposes a short public interface through a header file and stores implementation details in the corresponding source file. The system uses non-blocking periodic updates where practical, fixed-width integer types, named constants for assumptions, and simple functions that map closely to hardware behavior.

Known Limitations

  • PI controller gains are initial values and require physical tuning.
  • Encoder counts per revolution must match the final encoders.
  • The TFT display driver integration depends on the exact display controller.
  • Actuator polarity and travel timing should be verified on final hardware.
  • The physical custom PCB had not yet arrived, so PCB bring-up remains a planned validation step.
